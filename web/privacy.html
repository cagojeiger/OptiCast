DiodeCam · Privacy

Privacy

DiodeCam has no server of its own. Nothing you send or receive leaves your devices.

What the receiver page does with data

  • Camera. Frames are decoded in your browser, in a Web Worker, and discarded. No frame is stored or transmitted.
  • The received file. It is rebuilt in memory and kept in this browser's storage (IndexedDB) until you share it, receive the next file, press Reset, or 24 hours pass. It is never opened or uploaded; it is saved only when you tap Share or Download.
  • Progress. Pieces of an unfinished transfer are kept in IndexedDB for up to 7 days (128 MiB in total) so a closed tab can resume. Reset deletes them.
  • Preferences. The chosen camera, theme and download target are kept in localStorage. Clearing site data removes everything above.
  • Diagnostics. "Copy diagnostics" puts device, camera and recognition numbers on your clipboard, for you to paste where you choose. It never includes the file's name, size or content, the transfer ID, or device identifiers.

What the page does not do

  • No analytics, no cookies, no third-party scripts or fonts. The page loads only its own files.
  • No account, no sign-in.
  • No network request after the page and its files are loaded. Added to the home screen, it works offline.

Hosting

The page is static and served by GitHub Pages. GitHub may keep ordinary web-server logs (such as your IP address and the time of the request) under GitHub's privacy statement. Download links for the sender point at GitHub Releases, which is subject to the same statement.

The sender

The diodecam command reads only the file you name and draws it in the terminal. It makes no network connection and writes nothing except to the screen.

Storage origin

Browser storage is shared by every site on the same origin. While the page is served from *.github.io, other GitHub Pages sites of the same account could read it; that is why the received file is kept for a day at most and dropped once shared. A dedicated domain removes this sharing.
