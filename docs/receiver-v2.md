# OptiCast 수신기 v2 — 설계

대상은 **아이폰 Safari**(iOS 17 이상)이다. Android Chrome과 데스크톱 Chrome에서도 동작하게 한다.
프레임 규격은 [`protocol-v2.md`](protocol-v2.md)를 따른다. 송신 기본값은 24fps다.

## 1. 구성

```
카메라 ─ getUserMedia (1920×1080, frameRate ideal 60) ─ requestVideoFrameCallback
  │ 메인 스레드: drawImage → getImageData (스캔 폭 ?scan, 기본 min(영상 폭, 1920))
  ▼ 버퍼를 transfer로 넘김
Worker ─ WASM (Rust: opticast-vision + opticast-core)
  │ ① 휘도 변환 → ② 위치 표식 → ③ FI → ④ 호모그래피 → ⑤ 샘플링 → ⑥ 타일 디코드 → ⑦ RaptorQ 조립
  ▼ 프레임마다 통계 JSON, 완료 시 파일 바이트
UI (TypeScript) ─ 진행률·남은 시간·인식률·촬영 fps, 완료 시 저장/공유
```

- 비전, 타일, RaptorQ는 모두 Rust로 만들어 WASM 하나로 묶는다. 송신기와 같은 `opticast-core`를 쓴다.
- WASM은 `wasm32-unknown-unknown`으로 빌드하고 C ABI 함수만 내보낸다(`alloc`, `dealloc`, `receiver_*`).
  wasm-bindgen 같은 추가 도구가 없어도 `cargo build`만으로 빌드할 수 있다.

## 2. 비전 단계

1. **휘도**: RGBA를 Y = (77R + 150G + 29B) >> 8로 바꾼다.
2. **이진화**: 적분 영상으로 국소 평균 임계값을 구한다(창 크기는 영상 폭 / 40, 최소 15px).
   극성(글자색이 밝은지 어두운지)은 아직 모르므로 두 극성 모두에서 표식을 찾는다.
3. **위치 표식**: 행 단위로 런 길이를 보고 1:1:3:1:1 패턴(큰 표식)을 찾는다. 열과 대각선으로 교차 확인한 뒤
   후보를 묶어 중심과 모듈 크기(표식 폭 / 7)를 얻는다. 큰 표식 셋 중 나머지 둘과 이루는 각이 직각에 가장 가까운 것이 TL이다.
   TR과 BL은 외적의 부호로 구분한다. 이 단계에서 극성도 정해진다(표식의 바깥 고리 = 1).
4. **FI**: TL 표식과 위쪽 타이밍 줄(y = 5)의 전환점으로 x방향 모듈 위치를 맞춘다. 그 위치에서 y = 2, 3행을 읽어
   96비트를 얻고, 다수결과 CRC-8로 W, H, 프로필을 확정한다. 실패하면 BL 쪽 아래 사본을 읽는다.
5. **호모그래피**: 모듈 좌표 TL(5.5, 5.5), TR(W − 5.5, 5.5), BL(5.5, H − 5.5)과, 세 점에서 예측한 위치 근처에서 찾은
   BR 작은 표식(W − 4.5, H − 4.5)의 네 점으로 투영 변환을 구한다. 네 변의 타이밍 줄로 오차를 확인한다.
   오차가 0.3모듈을 넘으면 렌즈 왜곡 보정(가장자리 기준 보간)을 적용한다.
6. **샘플링**: 데이터 모듈마다 중심을 영상 좌표로 옮기고 3×3 평균 휘도를 읽어 국소 임계값과 비교한다.
   임계값에 가까운 모듈은 신뢰도가 낮다. 한 바이트에 이런 모듈이 몰리면 그 바이트를 RS 소실로 넘긴다(선택 사항).
7. **추적**: 직전 프레임의 표식 위치 주변을 먼저 찾는다. 실패하면 전체 탐색으로 돌아간다.
   목표는 아이폰 1080p에서 프레임당 20ms 이하다.

## 3. 타일과 조립

타일마다 백색화 해제 → RS → CRC-32C → 종류·태그 확인 → `opticast-core`의 수신기에 넣는다(규격 4·8절).
찢어진 화면에서 섞인 타일은 RS나 CRC에서 걸러지고, 나머지 타일은 그대로 쓴다.

## 4. 화면 (한국어, 세로 모바일 우선)

```
┌──────────────────────────────┐
│ OptiCast 수신기               │
│ 남은 조각 4,368개 · 약 17초    │  ← 상태 문구
│ ┌──────────────────────────┐ │
│ │   카메라 미리보기          │ │  ← 찾은 격자 테두리 표시
│ │   (격자 테두리 초록)       │ │
│ └──────────────────────────┘ │
│ report.pdf · 1.00 MB         │
│ 조각 6,120 / 10,488   58%    │
│ ██████████████░░░░░░░░░░     │
│ 촬영 30fps  처리 29fps        │
│ 타일 인식 91%  격자 199×106   │
│ ▸ 송신 fps를 올려도 됩니다     │  ← 인식률 안내
│ [카메라 시작] [초기화]         │
└──────────────────────────────┘
완료: ✓ SHA-256 확인 · [파일 저장] [공유]
```

- **남은 시간** = 남은 조각 수 ÷ 최근 5초 동안 들어온 새 조각의 초당 개수.
- **촬영 fps**: `track.getSettings().frameRate`와 rVFC로 실제로 잰 값을 함께 표시한다.
- **타일 인식률** = 최근 2초 동안 통과한 타일 ÷ 시도한 타일. 90% 이상이면 "송신 fps를 올려도 됩니다",
  70% 미만이면 "송신 fps를 낮추세요(-)", 격자를 찾지 못하면 "화면 전체가 들어오게 비추세요"라고 안내한다.
- **저장**: Blob URL과 `a.download`로 저장한다. iOS에서는 `navigator.share({ files })`가 되면 공유 버튼도 보여 준다.
- 진행 상태는 `IndexedDB`에 저장해서, 페이지를 다시 열어도 이어 받을 수 있게 한다(같은 전송 ID일 때).
- URL 옵션: `?scan=1280` (스캔 폭), `?debug=1` (격자·타일 오버레이).

## 5. 검증

- **Rust 단위 테스트**: 합성 카메라 영상(투영 왜곡, 흐림, 노이즈, 어두운/밝은 테마, 줄 간격)으로
  표식, FI, 호모그래피, 샘플링을 검사한다. 모듈 오류율과 타일 통과율을 잰다.
- **e2e**: Rust 송신기가 만든 실제 프레임 ANSI → TS 가상 터미널 → 카메라 시뮬레이터 → y4m(30fps, 송신 24fps 타이밍,
  화면 전환 중 찢어진 프레임 포함, 중간 합류) → Chrome 가짜 카메라 → 수신기 v2 → 다운로드한 파일을 원본과 바이트 비교.
- **실기기**: 아이폰 Safari에서 `pnpm dev:v2:lan`으로 접속해 촬영 fps, 처리 fps, 인식률, 완료 시간을 기록한다.
