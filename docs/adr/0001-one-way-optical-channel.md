# ADR 0001: SSH 터미널에서 폰 브라우저로 가는 단방향 광학 채널

- Status: Accepted
- Date: 2026-11-01

## Context

격리된 서버의 파일을 네트워크나 USB 없이 꺼내야 하는 경우가 있다(반출 승인은 전제다). 그런 서버에 사람이 닿는 길은
대개 SSH 터미널 하나뿐이고, 받는 쪽에는 사람이 들고 있는 스마트폰이 있다.

화면에서 카메라로 가는 빛은 한 방향으로만 흐른다. 수신기는 송신기에게 아무것도 알릴 수 없다. 받았다는 확인(ACK),
특정 조각 재전송 요청, 시간 동기화가 모두 불가능하다.

조건:
- 송신 쪽에는 GUI, 인터넷, 추가 장치가 없다. 출력 수단은 SSH 클라이언트의 글자 칸이다.
- 수신 쪽은 앱 설치 없이 폰 브라우저로 끝나야 한다.
- 수신자는 언제 촬영을 시작할지 모르고, 중간에 손이 흔들리거나 프레임을 놓친다.

## Decision

- 송신기는 파일을 **끝없이 방송**한다. 누가 받는지 모르며 알 필요도 없다.
  수신이 끝났는지는 폰만 알므로, 사람이 폰의 "수신 완료"를 보고 송신을 끝낸다(`q`).
- 송신 화면은 **SSH로 접속한 터미널의 글자 칸**을 기준으로 한다. 터미널 그래픽 프로토콜은 전제로 삼지 않는다.
- 수신기는 **폰 브라우저에서 여는 정적 웹 페이지**다(getUserMedia). 모든 처리는 기기 안에서 하고 아무것도 업로드하지 않는다.
- 피드백 없이 성립하도록 나머지 결정을 맞춘다. 순서와 무관한 조각([0006](0006-raptorq-fountain.md)),
  매번 다시 나오는 파일 정보([0007](0007-meta-tile-and-transfer-id.md)),
  프레임 일부만 읽혀도 쓰는 타일([0004](0004-tiles-and-tear-tolerance.md))이 그것이다.

## Rationale

대안과 선택 이유:

- **양방향(양쪽에 화면과 카메라)**: 서버 쪽에는 카메라가 없다.
- **소리(오디오 모뎀)**: SSH 터미널로는 소리를 낼 수 없다.
- **터미널 그래픽 프로토콜(sixel, kitty, iTerm2)**: 픽셀 단위로 그릴 수 있지만 SSH 클라이언트마다 지원이 다르다
  (PuTTY, macOS Terminal 등은 지원하지 않는다). 최소 공통분모가 아니다.
- **네이티브 앱**: 설치, 서명, 스토어 심사가 필요하다. 카메라 접근은 HTTPS 웹 페이지로 충분하다.
- **방송 + 사람이 종료** (채택): 피드백 채널이 없으니 "끝났는지"는 수신기만 안다. 송신을 계속 돌려도 손해가 없는
  부호([0006](0006-raptorq-fountain.md))를 쓰면, 끝내는 판단을 사람에게 맡겨도 된다.

## Consequences

- 송신기가 보여 줄 수 있는 진행 정보는 "원본 조각을 한 바퀴 다 보냈는가"와 "폰이 화면을 얼마나 봐야 하는가"뿐이다.
- 파일을 저장하기 전에 송신을 끄면 다시 받을 수 없다. 사용 순서는 "저장 → `q`"다.
- 수신 웹은 보안 컨텍스트(HTTPS)에서만 카메라를 쓸 수 있으므로 정적 HTTPS 호스팅이 필요하다([0011](0011-distribution.md)).
- 반출 통제(허용 목록, 민감정보 검사, 감사 기록)는 이 채널 밖의 책임이다. 송신 CLI는 크기 상한만 검사한다.
