# ADR 0005: 타일 안 오류 정정 — RS(128,108) + CRC-32C + 백색화

- Status: Accepted
- Date: 2026-11-01

## Context

카메라는 모듈을 자주 잘못 읽는다. 흐림, 센서 노이즈, 경계에 걸친 모듈, 화면 반사가 원인이다. 타일 하나는 프레임 간 부호의
조각 하나를 나른다. 결정할 것은 둘이다.

- 조금 틀린 타일을 고칠 것인가, 버릴 것인가.
- "잘못 고쳐진" 타일이 파일에 섞이지 않게 하려면 어떻게 하는가.

## Decision

- 타일 128바이트 = 데이터 108바이트 + Reed–Solomon 패리티 20바이트.
  GF(2⁸), 원시 다항식 0x11D, `reed-solomon` 0.2.1을 쓴다. 바이트 오류 10개 또는 소실 20개까지 고친다.
- 데이터 108바이트: 종류(1) · 플래그(1) · 태그(2) · SBN(1) · ESI(3) · 내용(96) · CRC-32C(4).
- RS로 고친 뒤 **CRC-32C**(Castagnoli, `crc` 3)로 한 번 더 확인한다. 틀리면 타일을 버리고, 위 계층은 그 타일을 "소실"로 본다.
- **백색화**: 타일 바이트를 타일 번호로 시드한 xorshift32 수열과 XOR한다. 파일 내용과 상관없이 화면이 고른 잡음처럼 보이고,
  큰 덩어리가 위치 표식처럼 보이는 일을 막는다.

## Rationale

대안과 선택 이유:

- **CRC만 두고 틀리면 버림**: 모듈 몇 개만 잘못 읽어도 타일 대부분을 잃는다. 처리량이 급락한다.
- **더 강한 RS(예: RS(128,96))**: 더 많이 고치지만 데이터가 11% 준다. 패리티 20바이트(약 16%)로 실측 인식률 99%를 얻었다.
- **LDPC, 터보 부호, 컨볼루션 부호**: 연판정에 강하지만 구현과 튜닝이 복잡하다. 128바이트짜리 짧은 블록에는 RS가 단순하고 충분하다.
  QR도 같은 선택을 했다.
- **BCH(비트 단위)**: 모듈 8개(= 1바이트)가 화면에서 붙어 있어 오류가 바이트 단위로 몰린다. 바이트 단위 부호인 RS가 맞다.
- **RS 결과를 그대로 믿기**: 오류가 정정 한계를 넘으면 RS가 엉뚱한 부호어로 "고칠" 수 있다. CRC가 그것을 걸러 낸다.
- **v1의 마스크 회전 대신 백색화**: 파운틴([0006](0006-raptorq-fountain.md))은 매번 새 조각을 보내므로 같은 그림이 반복되지 않는다.
  고정 자세에서 특정 프레임이 영원히 안 읽히던 문제가 구조적으로 사라진다. 백색화는 그 위에 화면 무늬만 고르게 한다.

## Consequences

- 타일 내용 96바이트가 곧 RaptorQ 조각 크기 T다([0006](0006-raptorq-fountain.md)).
- RS와 CRC를 이중으로 두어, e2e와 실기기 모두 최종 SHA-256 불일치가 0이었다(찢어진 타일은 버려지기만 했다).
- 향후 개선: 임계값 근처의 애매한 모듈을 RS 소실로 표시하면 정정 능력을 최대 두 배로 쓸 수 있다(설계에만 있고 미구현).
