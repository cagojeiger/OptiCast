# DiodeCam 웹 — 수신기

폰 브라우저(아이폰 Safari 기준)에서 카메라로 터미널을 찍어 파일을 복원한다. 모든 처리는 기기 안에서 하고 아무것도 업로드하지 않는다.
주소: https://cagojeiger.github.io/diodecam/

## 1. 화면

위에서 아래로: 제목과 **상태 한 줄** → 카메라 화면(찾은 격자에 테두리) → 진행 카드(이름·크기·전송 ID, 조각 수와 %, 막대, 조언 한 줄)
→ [카메라 시작/정지] [초기화] → 완료 카드(검증 후에만: ✓ SHA-256 확인, [파일 저장] [공유]) → 측정값 8칸
(촬영·처리 fps, 디코드 시간, 타일 인식률, 격자, 카메라 해상도, 다른 전송, 남은 시간).

## 2. 상태 흐름

```
[카메라 시작] → 카메라를 여는 중… → 송신 화면 전체가 들어오게 비추세요 → 격자를 찾았습니다 · 파일 정보를 기다리는 중…
  → 남은 조각 N개 · 약 T초 (· 이어 받기 M개) → 복원 + SHA-256 → 수신 완료. 파일을 저장하세요. (카메라 자동 정지)
```

| 상황 | 표시 |
|---|---|
| 검증 실패 | `검증 실패, 다시 모으는 중`, 저장분을 버리고 다시 모은다 |
| [카메라 정지] | `일시 정지됨 — 카메라를 다시 시작하면 이어서 받습니다.` |
| 상한 초과 | `파일이 너무 큽니다: N MiB > 한도 64 MiB (?max= 로 바꿀 수 있습니다)` (메모리를 잡기 전에 거부) |
| 디코더 오류 | `디코더 오류 — 새로고침하면 저장된 진행분에서 이어 받습니다.` (카메라 정지) |
| 카메라 불가 | 권한 거부, 또는 HTTPS/localhost가 아님 |

상태 한 줄은 우선순위가 가장 높은 하나만 보인다: 완료 > 상한 초과 > 오류 > 정지 > 찾는 중 > 받는 중.

## 3. 안내 규칙

- **테두리 색**(매 프레임): 타일 70% 이상 통과 초록, 1개 이상 주황, 0개 빨강.
- **조언**(최근 2초): 인식률 ≥ 90% "송신 fps를 올려도 됩니다 (+)", < 70% "송신 fps를 낮추세요(-)", 격자 없음 "화면 전체가 들어오게 비추세요".
- **남은 시간** = 남은 조각 ÷ 최근 5초 동안 새 조각의 초당 개수. 송신 상태 줄의 `phone needs`와 같은 식이다.

## 4. 저장과 이어 받기

- 완료 기준은 RaptorQ 복원 → (선언 크기까지만 inflate) → 크기 일치 → SHA-256 일치. 그 전에는 저장 버튼이 없다.
- [파일 저장]은 Blob 다운로드, [공유]는 iOS 공유 시트(AirDrop, 파일 앱). 파일을 자동으로 열지 않는다.
- 받은 타일은 5초마다(새 조각이 있을 때) 그리고 탭이 숨겨질 때 IndexedDB에 저장한다. META가 보이면 같은 전송 ID의 저장분을
  불러온다. 더 적은 조각으로 덮어쓰지 않고, 7일이 지나거나 합계 128 MiB를 넘으면 오래된 것부터 지운다. 완료되면 지운다.
- 받는 동안 Wake Lock으로 화면 꺼짐을 막는다.

## 5. 주소 옵션

`?max=256`(MiB, 1~512, 기본 64), `?scan=1920`(디코더에 넘기는 폭, 기본 min(영상 폭, 1920)), `?debug=1`(표식·타일 점과 내부 상태 JSON).

## 6. 영상 처리 (`crates/diodecam-vision`)

1. **휘도**: RGBA → Y = (77R + 150G + 29B) >> 8.
2. **이진화**: 적분 영상으로 국소 평균 임계값(창 = 영상 폭 / 40, 최소 15 px). 극성을 모르므로 두 극성 모두 시도한다.
3. **위치 표식**: 행마다 런 길이 1:1:3:1:1을 찾고 열·대각선으로 교차 확인한다. 직각에 가장 가까운 꼭짓점이 TL,
   외적의 부호로 TR/BL을 가른다. 표식의 바깥 고리 색이 극성(1)이다.
4. **타이밍 줄과 FI**: y = 5, x = 5 타이밍 줄의 경계로 W, H와 모듈 간격을 잡고 형식 정보(위 사본, 실패하면 아래 사본)로 확정한다.
5. **호모그래피**: TL(5.5, 5.5), TR(W − 5.5, 5.5), BL(5.5, H − 5.5)과 예측 위치 근처의 BR 작은 표식(W − 4.5, H − 4.5).
   네 타이밍 줄의 잔차가 0.3모듈을 넘으면 가장자리 기반 보정(렌즈 왜곡)을 섞는다.
6. **샘플링**: 모듈 중심의 3×3 평균을 7×7모듈 국소 평균과 비교한다.
7. **추적**: 다음 프레임은 직전 표식 근처부터 찾고, 실패하면 전체 탐색으로 돌아간다.

타일 디코드와 조립은 protocol 6절. 알려진 한계: 렌즈 왜곡 k1 > 0.018, 아이폰의 자동 렌즈 전환(가까이 찍을 때 초광각), 너무 작은 모듈.

## 7. 코드 구조 (`web/`, 빌드 없음)

| 파일 | 역할 |
|---|---|
| `index.html`, `style.css` | 화면 |
| `main.js` | 카메라(rVFC → canvas → Worker), 화면 갱신, 저장·공유, 이어 받기 |
| `worker.js` | WASM 수신기를 소유. 프레임마다 정확히 한 번 응답, 예외는 치명 오류 |
| `wasm.js` | `diodecam.wasm`(C ABI) 래퍼 |
| `metrics.js` | 인식률·속도·남은 시간·조언 같은 순수 함수 |
| `store.js` | IndexedDB 이어 받기 저장소 |

모든 내부 주소에 `?v=__V__`가 붙고, Pages 빌드가 커밋 해시로 바꾼다. 배포 직후에도 두 버전의 파일이 섞이지 않는다.
